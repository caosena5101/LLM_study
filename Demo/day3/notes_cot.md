# 进阶提示技巧学习笔记：CoT 与分支提示

> 日期: 2026-08-03 | 模型: deepseek-v4-flash

## 一、CoT 核心认知

### 1.1 论文来源
- **Chain-of-Thought Prompting**：Wei et al., *Chain-of-Thought Prompting Elicits Reasoning in Large Language Models*, NeurIPS 2022
- **Tree of Thoughts**：Yao et al., *Tree of Thoughts: Deliberate Problem Solving with Large Language Models*, NeurIPS 2023

### 1.2 为什么 CoT 有效？
1. **分解复杂度** — 多步推理拆成单步，每步搜索空间更小
2. **中间表示** — 推理步骤充当"工作记忆"，防止信息丢失
3. **概率路径** — 生成推理 token 为最终答案构建更精确的条件概率路径

### 1.3 三种 CoT 变体对比

| 变体 | 做法 | 需要示例 | 推理质量 | 适用场景 |
|---|---|---|---|---|
| Zero-shot CoT | 问题后追加"让我们一步一步思考" | ❌ | 中等 | 快速验证、简单推理 |
| Few-shot CoT | 提供 2~3 个带完整推理过程的示例 | ✅ | 最高 | 复杂推理、格式要求严格 |
| Auto-CoT | 自动生成多样化推理链示例 | 自动 | 高 | 大规模批量任务，减少人工设计成本 |

### 1.4 关键发现
- 简单题（如苹果题）：所有方法都能答对，CoT 优势不明显
- 复杂题（如水池注水）：Zero-shot 可能跳步出错，CoT 显著更稳
- Few-shot CoT 的推理格式最规范（因为示例锚定了输出结构）

## 二、Tree of Thoughts（ToT）

### 2.1 标准链 vs 树形分支

```
标准 CoT（线性链）:
  问题 → 步骤1 → 步骤2 → 步骤3 → 答案

Tree of Thoughts（树形分支）:
  问题 → 思路A → 步骤A1 → 步骤A2 → 答案A
       → 思路B → 步骤B1 → 步骤B2 → 答案B  ← 评估选优
       → 思路C → 步骤C1 →（剪枝）
```

### 2.2 ToT 核心步骤
1. 在每一步生成多个候选思路（分支）
2. 对每个分支进行自我评估（打分）
3. 使用 BFS/DFS 搜索最优路径
4. 适合需要"探索-回溯"的复杂问题（如 24 点游戏、创意写作规划）

### 2.3 本实验中的简化应用

用"分支提示"模拟 ToT 的核心思想——对同一问题假设不同场景/条件，生成多条推理路径，再对比结果。

本实验的三条路径：
- **路径 A（正向计算）**：按题目顺序逐步算
- **路径 B（逆向验证）**：假设答案，反向代入检验
- **路径 C（边界检查）**：检查是否有遗漏条件或边界情况

### 2.4 什么时候用分支提示？
- 答案不确定、需要高置信度
- 题目有歧义或容易忽略隐含条件
- 需要向用户展示"为什么这个答案是对的"

## 三、实验设计

### 3.1 实验矩阵

| 编号 | 方法 | 提示策略 | 预期效果 |
|---|---|---|---|
| ① | Zero-shot 直接回答 | 仅给问题，要求直接输出答案 | 简单题正确，复杂题可能出错 |
| ② | Zero-shot CoT | 问题 + "让我们一步一步思考" | 激活推理链，准确率提升 |
| ③ | Few-shot CoT | 2 个带推理过程的示例 + 问题 | 推理格式最规范，准确率最高 |
| ④ | 分支提示（ToT 简化） | 假设不同场景，生成多条路径 | 展示多角度推理能力 |

### 3.2 测试题目
- **基础题**：小明有10个苹果，买了3个，吃了2个，还剩几个？（答案 11）
- **进阶题**：水池进出水问题，净注入 2 吨/小时，从 10 吨注到 50 吨需 20 小时

## 四、DeepSeek V4 Flash 观察

- 对"让我们一步一步思考"指令响应良好，能生成清晰的分步推理
- Few-shot 示例中的 `#### 数字` 格式被严格模仿
- 分支提示中能较好地区分三条路径，不混淆
- `temperature=0.3` 时推理稳定性好，`temperature=0.7` 时偶尔跳步
- DeepSeek V4 默认开启 thinking 模式，最终答案在 `content`，token 用尽时会落到 `reasoning_content`，代码已做兜底提取

## 五、实用建议

1. **简单任务**：Zero-shot 足够，不需要 CoT（省 token）
2. **多步推理**：必须用 CoT，推荐 Few-shot CoT
3. **高风险决策**：用分支提示做多路径验证
4. **生产环境**：在 system prompt 中固定推理格式（如 `#### 数字`），方便下游解析
5. **答案提取**：用正则按优先级匹配多种格式（`#### n` / `答案是 n` / `还剩 n 个`），最后兜底取最后一个独立数字

## 六、扩展练习

替换 `HARD_Q` 为更难的"火车过桥"问题，可更明显地体现 CoT 优势：

```python
HARD_Q = (
    "一列火车长200米，以每秒20米的速度通过一座长800米的桥。"
    "从火车头进入桥到火车尾离开桥，共需多少秒？"
)
CORRECT_HARD = "50"  # (200+800)/20 = 50秒
```

这类问题中，Zero-shot 经常忘记加上火车自身长度，而 CoT 通过分步推理能显著降低这类错误率。
