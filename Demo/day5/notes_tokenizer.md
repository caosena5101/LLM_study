# Day 5 · 分词器（Tokenization）与嵌入（Embedding）学习笔记

## 一、为什么需要分词（Tokenization）

大语言模型本质上是做大量矩阵乘法的神经网络，它**看不懂文字，只能处理数字**。分词器（Tokenizer）就是连接人类语言与机器计算的桥梁，核心工作分两步：

1. **切分（Tokenize）**：把文本拆成模型能识别的最小单元（Token）。
2. **映射（Mapping to IDs）**：查内置词典（Vocabulary），把每个 Token 映射为唯一的数字索引（Input IDs）。

### 为什么不直接按字 / 按词处理？

| 方案 | 问题 |
|---|---|
| 按**字符** | 序列过长（一个英文单词就要 4-10 个 token）；单个字母没有语义。 |
| 按**单词** | 词表膨胀到百万级；无法处理变形词（running / unbelievable / OOV 未登录词）。 |
| **子词（Subword）** | 折中：高频词完整保留，低频词拆成有意义的子词，控制词表大小 + 解决 OOV。 |

## 二、三大主流分词算法对比

| 算法 | 核心机制 | 特点 | 代表模型 |
|---|---|---|---|
| **BPE** (Byte Pair Encoding) | 从字符级开始，反复合并出现频率最高的字节对 | 简单直观，有效处理 OOV，多语言支持好 | GPT 系列 |
| **WordPiece** | 基于最大似然估计，优先合并能最大程度提升语言模型概率的子词对 | 用 `##` 标记词内子词（如 `play` / `##ing`），推理采用最长匹配优先 | BERT 系列 |
| **SentencePiece** | 语言无关的通用框架，将文本视为 Unicode 序列，不依赖空格分词 | 对中文、日文等无天然空格分隔的语言极其友好 | T5、通义千问、LLaMA |

### BPE 训练流程（直观理解）

```
初始词表: l, o, w, e, r, n, s, t, ...
统计词频: low (5), lower (2), newest (6), widest (3)
反复合并最高频字节对:
  e + s -> es (出现 9 次)
  es + t -> est (出现 9 次)
  ...
最终词表: l, o, w, e, r, n, s, t, es, est, low, ...
```

### WordPiece 与 BPE 的区别

- BPE 选**频率最高**的字节对合并。
- WordPiece 选**使语言模型似然最大化**的字节对合并（贪心 + 概率准则）。
- WordPiece 用 `##` 表示"接在词内部"的子词，BPE 一般用特殊字符（如 GPT 的 `</w>`）或直接无标记。

## 三、Token 与 Embedding 的区别

| 概念 | 是什么 | 例子 |
|---|---|---|
| **Token** | 模型处理文本的最小**离散单位** | 一个汉字、一个英文子词、一个标点 |
| **Embedding** | Token ID 映射为的**高维连续向量** | 512 维浮点数组 |

### 为什么要 Embedding？

Token 变成数字 ID 后，彼此之间**没有语义联系**：ID=100（猫）和 ID=200（狗）在数字上没有"更近"的关系，反而可能 ID=100 和 ID=101（飞机）更近。

Embedding 层把这些孤立的数字 ID 映射为高维连续向量。在这个向量空间中：
- "猫"和"狗"的距离 < "猫"和"飞机"的距离
- 模型才能真正"理解"语义

### Embedding 的几何性质

- 同义词在向量空间中靠近。
- 类比关系可用向量加减表示：`国王 - 男人 + 女人 ≈ 女王`。
- 维度越高，表达能力越强，但计算/存储成本越高（BERT 768 维，GPT-2 768/1280，GPT-3 12288）。

## 四、核心认知：大模型上下文长度限制的底层原因

**为什么模型不能无限记忆？**

大模型上下文窗口（Context Window，如 8K、32K、128K）限制的是 **Token 的数量**，而不是字符数或字数。

### 原因一：Self-Attention 的 O(N²) 复杂度

Transformer 核心的自注意力机制需要计算**每个 Token 与其他所有 Token** 的关联：

$$
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V
$$

- 注意力矩阵大小 = **N × N**（N 是 Token 数）
- 计算复杂度：**O(N² · d)**
- 显存占用：**O(N²)**（存注意力矩阵）+ O(N · d)（存 KV cache）

| N (Token) | N² (注意力矩阵元素) | 相对 128 的倍数 |
|---|---|---|
| 128 | 16,384 | 1× |
| 1,024 | 1,048,576 | 64× |
| 8,192 | 67,108,864 | 4,096× |
| 32,768 | 1,073,741,824 | 65,536× |

→ N 翻倍，计算量变 **4 倍**。8K vs 128，自注意力计算量放大 **4096 倍**。

### 原因二：语言差异导致 Token 密度不同

| 语言 | 1 个字/词 ≈ Token 数 | 说明 |
|---|---|---|
| 中文 | 1 字 ≈ 1~2 Token | tiktoken 对中文不友好，常 1 字拆 2-3 个 BPE 字节 |
| 英文 | 1 词 ≈ 1.3 Token | 高频词 1 个 token，长词拆 2-3 个 |

→ 同样的上下文窗口，**能容纳的中文文本量比英文少**。这也是为什么国产大模型（通义、文心）常用 SentencePiece 优化中文 token 效率。

### 原因三：KV Cache 显存线性增长

推理时为了不重复计算历史 token 的 K/V，模型把它们缓存下来（KV Cache）：
- 显存占用 = `2 × N × d × 层数 × 精度字节`
- GPT-3 175B：1 个 token 的 KV cache ≈ 3.4 MB，32K 上下文 ≈ 110 GB

## 五、实验观察总结（基于 tokenizer_lab.py）

### 实验一：tiktoken (GPT-4 BPE)
- 中文 1 字常被拆成 2-3 个 token（BPE 字节级合并）。
- 英文高频词 1 个 token，长词拆 2-3 个子词。
- **同样语义长度，中文 token 数 > 英文**。

### 实验二：BERT WordPiece
- 中文：字级别分词，1 汉字 = 1 token。
- 英文：用 `##` 标记词内子词，如 `playing` → `[play, ##ing]`。
- 自动加 `[CLS]` (101) 和 `[SEP]` (102) 特殊 token。

### 实验三：Token 估算函数
- `tiktoken.encoding_for_model(model)` 按模型名查 BPE 编码。
- 未识别模型回退到 `cl100k_base`（GPT-4 系列）。
- 实测：1000 字中文 ≈ 1500-2000 token，8K 窗口约能装 4-5 千字。

### 实验四：注意力热力图 + 复杂度曲线
- 热力图每行和=1（softmax 归一化）。
- 复杂度曲线 N² 在 log-log 图上呈直线，斜率=2，直观体现 O(N²)。

## 六、面试速记卡（口头回答模板）

### Q1：为什么大模型需要"分词"而不是直接按字或按词处理？

> 按"字符"处理会导致序列过长，且单个字母无意义；按"单词"处理会导致词表膨胀到百万级，且无法处理变形词（如 running/unbelievable）和未登录词。**子词分词（如 BPE）是折中方案**：高频词完整保留，低频词拆成有意义的子词，既控制了词表大小（通常 3-10 万），又解决了 OOV 问题。

### Q2：BPE / WordPiece / SentencePiece 的区别？

> - **BPE**：按频率贪心合并字节对，简单直观，GPT 系列在用。
> - **WordPiece**：按语言模型似然贪心合并，用 `##` 标记词内子词，BERT 系列在用。
> - **SentencePiece**：语言无关，把文本当 Unicode 序列，不依赖空格，对中日韩友好，T5/LLaMA 在用。

### Q3：Token 和 Embedding 的区别？

> Token 是离散的最小文本单位；Embedding 是把 Token ID 映射成的高维连续向量。Token ID 之间没有语义关系，Embedding 让"猫"和"狗"在向量空间靠近，模型才能真正理解语义。

### Q4：为什么需要注意力机制（Attention）？

> 传统 RNN 逐字顺序处理，长距离依赖容易丢失。注意力机制让模型在处理每个词时能"看一眼"所有其他词，按相关性动态分配权重（Q 提问、K 应答、V 传递内容），距离=1，全图并行。

### Q5：多头注意力（Multi-Head Attention）的作用？

> 单头只能学一种关系。多头让模型并行开启多个"视角"：一个头关注语法结构（主谓宾），一个头关注指代关系（代词指谁），一个头关注位置关系。多头并行后 Concat + Linear 融合，**参数量不变**，只是把 `d_model` 切成多份在不同子空间使用。

### Q6：大模型上下文长度限制的底层原因是什么？（核心）

> 底层原因是 **Token 数量限制**而非字数限制。Transformer 自注意力计算复杂度与 Token 数的**平方**成正比 O(N²)。Token 越多，显存占用和推理耗时指数上升。同时不同语言 Token 密度不同（中文 1 字 ≈ 1-2 token，英文 1 词 ≈ 1.3 token），导致同样窗口能装的中文比英文少。扩大上下文需要更多显存 + 更长推理时间，这就是为什么长上下文是稀缺能力。

## 七、扩展思考

1. **为什么 GPT-4o 用 `o200k_base` 而不是 `cl100k_base`？** 新版编码压缩了多语言（尤其中文/日文）的 token 数，让同样上下文窗口能装更多非英文内容。
2. **为什么 LLaMA / Qwen 用 SentencePiece 而不是 BPE？** SentencePiece 把文本当 Unicode 流，不依赖空格预分词，对中日韩等无空格语言天然友好。
3. **KV Cache 量化**：把 KV cache 从 fp16 量化到 int8/int4，可显著降低长上下文显存占用，是当前长上下文优化的关键方向。
4. **Ring Attention / Flash Attention**：通过分块计算 + IO 优化，把 O(N²) 注意力的实际显存占用降到 O(N)，是支持百万级上下文的技术基础。
