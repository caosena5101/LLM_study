# 大模型核心参数学习笔记

> 日期: 2026-08-04 | 模型: deepseek-v4-flash

## 一、核心参数解析

大模型在推理时并非"确定性地输出一个答案"，而是在每一步对词表中所有 token 计算概率分布，再从中采样。以下参数控制着"如何采样"：

| 参数 | 范围 | 作用机制 | 直觉理解 |
|------|------|----------|----------|
| temperature | 0 ~ 2.0 | 对 logits 除以温度值后再 softmax。温度越低分布越尖锐，越高越平坦 | 0=考试（唯一答案）；1.5=头脑风暴（天马行空） |
| top_p (nucleus) | 0 ~ 1.0 | 只从累积概率达到 p 的最小 token 集合中采样 | 0.1=只看最可能的几个词；0.9=几乎看全部 |
| frequency_penalty | -2.0 ~ 2.0 | 对已出现过的 token 施加惩罚，降低其再次被选中的概率 | 正值=防止复读机；负值=鼓励重复 |
| presence_penalty | -2.0 ~ 2.0 | 对已出现过的 token 施加固定惩罚（不论出现几次） | 鼓励引入新话题 |
| max_tokens | 正整数 | 限制输出的最大 token 数 | 控制回答长度 |

## 二、Temperature 规律总结

- Temperature = 0   -> 贪心解码，完全确定，适合精确任务
- Temperature = 0.3  -> 低随机，适合代码/数据提取
- Temperature = 0.7  -> 平衡点，适合通用对话/写作
- Temperature = 1.0  -> 模型原始分布
- Temperature = 1.5+ -> 高随机，适合创意/头脑风暴，但可能不通顺

**核心公式**: `P(token_i) = softmax(logit_i / T)`

- T↓ -> 分布尖锐 -> 确定性↑
- T↑ -> 分布平坦 -> 随机性↑

### 数学本质

设模型输出的原始 logits 为 `z_1, z_2, ..., z_V`（V 为词表大小），则：

- T -> 0：概率集中在 logit 最大的 token 上 -> 近似贪心解码（greedy），输出确定
- T = 1：使用原始概率分布 -> 模型"默认行为"
- T > 1：概率分布被拉平 -> 低概率 token 也有机会被选中 -> 输出更随机、更有创意

### 实验观察

- T=0：10 次输出完全相同（多样性=10%），每次都是同一首诗
- T=0.7：9/10 个不同输出（多样性=90%），保持连贯但有变化
- T=1.5：10/10 个不同输出（多样性=100%），可能出现跳跃/不通顺

## 三、幻觉识别与防范

模型以自信、流畅的语气输出事实上不存在或错误的信息。

### 产生原因

1. 模型本质是"概率续写器"，不是"知识检索器"
2. 训练数据有截止日期，模型不知道"自己不知道"
3. 面对模糊/虚构实体时，模型倾向"编造合理答案"而非拒绝回答

### 常见幻觉类型

| 类型 | 示例 |
|------|------|
| 虚构事实 | 编造不存在的论文、事件 |
| 张冠李戴 | 把 A 的成就安在 B 头上 |
| 虚假引用 | 编造不存在的法律条文/书名 |
| 时间错乱 | 把历史人物放到现代场景中 |

### 幻觉高发场景

1. 虚构人物 + 真实背景（张三丰 + 2023 年）
2. 虚构作品（不存在的书名/电影）
3. 虚构人物 + 真实奖项（王小明 + 诺贝尔奖）
4. 未来/不存在的技术特性（Python 4.0 quantum decorator）
5. 虚构历史事件（爱因斯坦访华）

### 防范策略

- **Prompt 层面**: 加入"如果不确定请说不知道"
- **系统层面**: RAG 检索增强
- **后处理**: 事实核查 + 交叉验证
- **参数层面**: 降低 temperature 减少随机编造

## 四、上下文窗口

- 上下文窗口 = 模型单次推理能"看到"的最大 token 数（输入 + 输出之和）
- 限制的是 **Token 数量**，不是字数
- 底层原因: Self-Attention 的 O(N²) 计算复杂度
- 中文 ≈ 1 字 = 1~2 tokens；英文 ≈ 1 词 = 1.3 tokens
- 超出窗口 -> 报错或截断（不是"忘记"，是根本放不下）

### 底层限制原因

- **显存瓶颈**: Self-Attention 需要存储 O(N²) 的注意力矩阵
- **训练分布**: 模型只在固定长度上训练过，超出后位置编码外推失效
- **推理成本**: KV Cache 随序列长度线性增长

## 五、参数选择速查表

| 任务 | temperature | top_p | freq_penalty |
|------|-------------|-------|--------------|
| 代码生成 | 0 ~ 0.2 | 0.9 | 0 |
| 数据提取/JSON | 0 ~ 0.1 | 0.95 | 0 |
| 通用对话 | 0.5 ~ 0.8 | 0.95 | 0 |
| 创意写作 | 0.8 ~ 1.2 | 0.98 | 0.3 |
| 头脑风暴 | 1.2 ~ 1.5 | 1.0 | 0.5 |

## 六、验收要点

| 验收项 | 标准 | 判断方式 |
|--------|------|----------|
| Temperature=0 | 10 次输出完全相同（多样性=0%或极低） | 脚本自动统计 |
| Temperature=0.7 | 输出有明显变化但保持连贯 | 多样性≈80-100% |
| Temperature=1.5 | 输出高度随机，可能出现不通顺/跳跃 | 多样性=100% |
| 幻觉识别 | 至少识别出 3 个幻觉实例 | 检查报告中标记 [可能产生幻觉] 的条目 |
| 规律总结 | 能说出"温度越高->分布越平->采样越随机->多样性越高" | 报告总结部分 |
| 上下文窗口解释 | 理解 Token 数限制与 O(N²) 复杂度 | 口头解释 |
