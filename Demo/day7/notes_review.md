## 二、自测题详解（做什么）

> 使用方法：先不看答案，口头或书面回答。然后对照评分标准自评。

### ① 什么是注意力机制？

**✅ 满分回答要点（5/5）**：

- 注意力机制让序列中每个位置能直接关注所有其他位置（解决 RNN 长距离依赖）
- 核心是 QKV 三元组：Query（查询）、Key（键）、Value（值）
- 多头注意力让模型在不同子空间学习不同关注模式

**⚠️ 常见扣分点**：

- 只说"让模型关注重要信息"但没提 QKV（-2 分）
- 没提缩放因子（-1 分）
- 没解释为什么需要多头（-1 分）

**🔑 一句话速记**：

> 注意力 = 用 Q 和 K 算相关性权重，对 V 加权求和，实现任意位置间的直接信息交互。

**📐 公式**：

```
Attention(Q, K, V) = softmax(Q·K^T / √d_k) · V
```

- `√d_k` 缩放因子：防止点积过大导致 softmax 进入饱和区（梯度消失）
- 多头：`MultiHead = Concat(head_1, ..., head_h) · W_O`，每头在不同子空间学习不同模式

### ② 解释 CoT 提示的原理

**✅ 满分回答要点（5/5）**：

- CoT = Chain-of-Thought，在 prompt 中加入"让我们一步一步思考"触发中间推理步骤
- 原理 1 - 分解复杂度：多步推理拆成单步，每步搜索空间更小
- 原理 2 - 工作记忆：生成的推理 token 充当中间表示，防止信息丢失
- 原理 3 - 概率路径：推理过程为最终答案构建更精确的条件概率路径
- Few-shot CoT > Zero-shot CoT，因为示例锚定了推理格式

**⚠️ 常见扣分点**：

- 只说"让模型慢慢想"但没提三个原理（-3 分）
- 没区分 Zero-shot 和 Few-shot（-1 分）

**🔑 一句话速记**：

> CoT 通过生成中间推理步骤，将复杂问题分解为简单子问题，同时为模型提供"工作记忆"。

### ③ 温度参数如何影响输出？

**✅ 满分回答要点（5/5）**：

- T → 0：分布极尖锐，近似贪心解码，输出确定可复现
- T = 1：使用原始概率分布，模型默认行为
- T > 1：分布被拉平，低概率 token 有机会被选中，输出更随机 / 有创意
- 实际选择：代码 / 提取用 0~0.2；对话用 0.5~0.8；创意用 1.0~1.5

**⚠️ 常见扣分点**：

- 只说"温度高更随机"但没提数学原理（-2 分）
- 没给出实际使用建议（-1 分）
- 混淆 temperature 和 top_p（-2 分）

**🔑 一句话速记**：

> 温度是 softmax 的"锐度旋钮"：低温 = 确定性，高温 = 多样性，本质是对 logits 做除法改变概率分布形状。

**📐 公式**：

```
P(token_i) = exp(logit_i / T) / Σ_j exp(logit_j / T)
```

| T 值 | 行为 | 适用场景 |
|---|---|---|
| 0 ~ 0.2 | 近贪心，确定可复现 | 代码生成、JSON 提取 |
| 0.5 ~ 0.8 | 平衡点 | 通用对话、写作 |
| 1.0 | 模型原始分布 | 默认行为 |
| 1.2 ~ 1.5 | 高随机、有创意 | 头脑风暴、创意写作 |

### ④ 如何计算 API 调用成本（基于 token）？

**✅ 满分回答要点（5/5）**：

- LLM 按 token 数量计费，不是按字数 / 字符数
- 输入 token 和输出 token 通常单价不同（输出更贵，约 2-4 倍）
- 公式：`总费用 = 输入 tokens × 输入单价 + 输出 tokens × 输出单价`
- 中文 1 字 ≈ 1-2 tokens，英文 1 词 ≈ 1.3 tokens（因分词器而异）
- 可通过 API 返回的 `usage` 字段获取实际消耗

**⚠️ 常见扣分点**：

- 以为按字数计费（-3 分）
- 不知道输入输出单价不同（-2 分）
- 没提中英文 token 密度差异（-1 分）

**🔑 一句话速记**：

> 费用 = Σ(token 数 × 单价)，输入输出分开计价，中文比英文费 token。

**📐 计算示例**（DeepSeek-V4 Flash 参考价）：

| 场景 | 输入 tokens | 输出 tokens | 输入费 | 输出费 | 总费 |
|---|---|---|---|---|---|
| 短对话（中文 50 字） | 80 | 120 | ¥0.008 | ¥0.024 | ¥0.032 |
| 长文摘要（中文 2000 字） | 3500 | 800 | ¥0.35 | ¥0.16 | ¥0.51 |
| 代码生成（英文 500 词） | 650 | 1200 | ¥0.065 | ¥0.24 | ¥0.305 |
| CoT 推理（100 字问 + 500 字答） | 180 | 900 | ¥0.018 | ¥0.18 | ¥0.198 |

### ⑤ 为什么大模型会产生幻觉？

**✅ 满分回答要点（5/5）**：

- 本质原因：LLM 是概率续写器，不是知识检索器，目标是"生成流畅文本"而非"保证事实正确"
- 训练数据截止：模型不知道自己的知识边界，无法区分"不知道"和"知道但忘了"
- 过度自信：softmax 归一化使输出总是呈现确定语气，即使不确定
- 模式补全倾向：面对模糊 query 时，模型倾向于"编造合理答案"而非拒绝
- 防范措施：RAG、要求引用来源、降低 temperature、添加拒绝指令、事实核查

**⚠️ 常见扣分点**：

- 只说"模型会编造"但没分析深层原因（-3 分）
- 没提防范措施（-1 分）
- 把幻觉等同于"模型笨"（-2 分，幻觉是架构特性不是 bug）

**🔑 一句话速记**：

> 幻觉是 LLM 作为"概率语言模型"的固有特性：它优化的是文本流畅性而非事实准确性，不知道自己不知道。

**常见幻觉类型**：

| 类型 | 示例 |
|---|---|
| 虚构事实 | 编造不存在的论文、事件 |
| 张冠李戴 | 把 A 的成就安在 B 头上 |
| 虚假引用 | 编造不存在的法律条文 / 书名 |
| 时间错乱 | 把历史人物放到现代场景中 |
