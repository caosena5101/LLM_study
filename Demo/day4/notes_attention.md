## 一、为什么需要注意力机制？

### 1.1 RNN/LSTM 的痛点

在 Transformer 之前，序列建模主要靠 RNN/LSTM，它们是**串行**的：第 t 步必须等第 t-1 步算完。

| 痛点 | 表现 |
|---|---|
| 无法并行 | 训练极慢，GPU 利用率低 |
| 长距离依赖困难 | 信息经过多步传递后衰减 / 消失，"开头的信息"到结尾已经模糊 |

### 1.2 注意力的核心思想

让序列中的**每个位置都能直接看到所有其他位置**，通过计算"相关性"动态聚合信息。

- 任意两点距离 = 1（不再随位置衰减）
- 全图并行计算（一次矩阵乘法搞定）
- 根据内容决定关注谁，而非固定窗口

## 二、QKV 机制：软检索（Soft Retrieval）

自注意力本质是一次"软检索"：用 Q 去和所有 K 比相似度，按相似度对所有 V 加权求和。

| 符号 | 含义 | 类比 |
|---|---|---|
| Q (Query) | 查询向量："我在找什么？" | 搜索引擎的搜索词 |
| K (Key) | 键向量："我有什么标签？" | 网页的标题/关键词 |
| V (Value) | 值向量："我的具体内容" | 网页的实际内容 |

### 2.1 计算公式

$$
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V
$$

### 2.2 五步拆解（对应 `SingleHeadSelfAttention.forward`）

1. **线性投影**：`Q = W_q @ x`，`K = W_k @ x`，`V = W_v @ x` —— 三个独立可学习的投影矩阵，让模型学会"从不同角度看同一输入"。
2. **相似度**：`scores = Q @ K^T` —— 点积越大越相关，得到 `(B, L, L)` 的分数矩阵。
3. **缩放**：`scores / √d_k` —— 防止点积过大。
4. **归一化**：`softmax(dim=-1)` —— 每行之和为 1，得到注意力权重（概率分布）。
5. **加权求和**：`context = attn_weights @ V` —— 用权重对 V 加权求和，得到融合后的表示。
6. **输出投影**：`output = W_o @ context` —— 再做一次线性变换，增加表达能力。

### 2.3 为什么除以 √d_k？

- 当 `d_k` 较大时，`Q @ K^T` 的值会变大（点积是 d_k 个乘积之和）。
- 过大的值进入 softmax 后梯度趋近于 0（饱和区），训练不动。
- 除以 `√d_k` 把方差稳定回 1，让 softmax 处于梯度友好的区间。

## 三、多头注意力：并行学习多种关注模式

### 3.1 为什么单头不够？

单头注意力只能学到**一种**关注模式。但语言中的关系是多维度的：

- 语法关系（主谓一致）
- 语义相似性
- 位置相邻关系
- 指代关系（"他" 指代谁）

单头难以同时表达这些不同维度的关系。

### 3.2 多头怎么做？

把 `d_model` 切成 `h` 个 `d_k = d_model / h` 的子空间，每个子空间独立做一次注意力：

```
Q, K, V: (B, L, D) -> (B, H, L, d_k)   # 切头
每个头独立算 attention                # H 个 (B, L, L) 注意力矩阵
concat 回 (B, L, D) -> W_o 线性变换     # 融合多头信息
```

### 3.3 多头的作用

- **并行学习**：每个头在不同子空间学习不同的关注模式。
- **表达力增强**：相当于多个"视角"看同一序列，再融合。
- **可解释性**：可视化每个头的注意力热力图，能看到不同头关注不同的关系。

### 3.4 与单头的参数量对比

- 单头：4 个 `(D, D)` 矩阵 = `4D²` 参数
- 多头（h 头）：4 个 `(D, D)` 矩阵 = `4D²` 参数（**总参数量不变**，只是在计算时拆分到子空间）

> 多头不是堆参数，而是**重塑**参数的使用方式。

## 五、关键代码理解

### 5.1 `torch.bmm` vs `torch.matmul`

- `torch.bmm`：仅支持 3D `(B, n, m) @ (B, m, p) -> (B, n, p)`，单头用。
- `torch.matmul`：支持任意广播，多头用 `(B, H, L, d_k) @ (B, H, d_k, L)`。

### 5.2 多头拆分与拼接

```python
# 拆头: (B, L, D) -> (B, L, H, d_k) -> (B, H, L, d_k)
Q = self.W_q(x).view(B, L, H, d_k).transpose(1, 2)

# 拼头: (B, H, L, d_k) -> (B, L, H, d_k) -> (B, L, D)
context = context.transpose(1, 2).contiguous().view(B, L, D)
```

- `transpose(1, 2)`：把 head 维度提到前面，便于并行计算。
- `contiguous()`：transpose 后内存不连续，view 前必须调用。
- `view(B, L, D)`：把 H × d_k 拼回 D。

### 5.3 `return_attn` 的作用

注意力权重是中间结果，正常 forward 不返回。但**可视化 / 解释性**需要它，所以加了一个开关。这也是 PyTorch 中常见的设计模式。

## 六、口头解释要点（验收用）

### Q1：为什么需要注意力？

> RNN 串行计算慢、长距离依赖弱。注意力让序列中任意两点直接连接（距离=1），支持全图并行，且根据内容动态决定关注谁，而不是固定窗口。这是 Transformer 能取代 RNN 的关键。

### Q2：多头注意力的作用？

> 单头只能学一种关注模式。多头把 d_model 切到多个子空间并行学习，每个头可能关注语法、语义、位置、指代等不同关系，最后 Concat + Linear 融合，相当于多个"视角"看同一序列。参数量不变，表达力增强。

### Q3：为什么除以 √d_k？

> 点积是 d_k 个乘积之和，d_k 大时值会很大，softmax 进入饱和区梯度消失。除以 √d_k 把方差稳定到 1，保证梯度稳定。

### Q4：Q、K、V 为什么要用不同的投影矩阵？

> 同一输入从不同角度被"提问"：Q 决定"我在找什么"，K 决定"我能被谁找到"，V 决定"我提供什么内容"。如果三者共享矩阵，就退化成"自相似"，表达力大幅下降。

## 七、扩展思考

1. **位置编码**：本实验输入是随机向量，没有位置信息。真实 Transformer 会加上位置编码（sinusoidal 或 learned），否则注意力是"位置无关"的。
2. **Causal Mask**：解码器中需要遮住"未来"位置，对应 GPT 类模型。可在 softmax 前把上三角设为 `-inf`。
3. **Cross Attention**：Q 来自一个序列（如解码器），K/V 来自另一个序列（如编码器），用于 Seq2Seq。
4. **与微调的关系**：理解注意力是后续 LoRA / QLoRA 微调的基础 —— LoRA 就是在 W_q、W_v 旁加低秩矩阵。
